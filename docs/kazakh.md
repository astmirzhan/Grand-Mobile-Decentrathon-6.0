# Казахская часть locqa: глоссарий, языковые проверки, метрики

Эта часть переводит знание казахского языка в правила для кода и честно измеряет качество
инструмента. Подробности методов и цифры — в [methodology.md](methodology.md).

## Что входит

| Файл | Что делает |
|---|---|
| `glossary.csv` | 104 игровых термина: `ru, kk, en, comment, allowed_variants, strict` |
| `brands.txt` | бренды и имена, которые не переводятся (whitelist для `same_as_source`) |
| `locqa/lang/kk.py` | правила языка: пары букв, аффиксы, гармония гласных, основа слова |
| `locqa/glossary.py` | загрузка глоссария и поиск термина по основе слова в ru и kk |
| `locqa/checks/kazakh.py` | 4 проверки: `orthography`, `suffix_harmony`, `glossary_violation`, `inconsistent_term` |
| `locqa/lang/translit.py` | транслитерация в казахскую латиницу (алфавит 2021 года) |
| `locqa/lang/kk_runtime.py` + `integrations/flutter/kk_affix` | правильное окончание для подставляемого значения во время игры (Python и Dart) |
| `locqa/lang/plural.py` | формы множественного числа по языкам (CLDR): `...Few/...Many` не нужны в казахском |
| `scripts/compare_baselines.py` | сравнение с готовыми линтерами и базовыми правилами на одних данных |
| `scripts/mutate_kk.py` | recall: вносит известные ошибки и проверяет, найдены ли они с правильным типом |
| `scripts/precision_sample.py` | precision: выборка находок для ручной разметки и подсчёт |
| `scripts/translit_kk.py` | ARB в латиницу + список строк, которые стали заметно длиннее |
| `tests/test_kk_lang.py`, `test_glossary.py`, `test_kazakh_checks.py`, `test_translit.py`, `test_metrics_scripts.py` | тесты на синтетических данных |

Данных кейса в репозитории нет: тесты используют маленькие придуманные строки.

## Главная идея

Подложенная ошибка — это точечное искажение в согласованном файле из 5 500 строк.
Поэтому эталоном служит сам `intl_kk.arb`, а не внешний словарь:

- слово встречается 1 раз, а то же слово с казахской буквой — 55 раз: это опечатка;
- термин в 85 из 87 строк переведён одним словом, а здесь другим: это несогласованность.

Каждая находка объясняется числами из файла, поэтому её легко проверить.

## Четыре проверки

| Тип | Что ловит | Пример | Severity |
|---|---|---|---|
| `orthography` | русская буква вместо казахской; латинская буква внутри кириллического слова | `кайта → қайта`, `бөлімiне` (латинская i) | medium |
| `suffix_harmony` | аффикс сразу после плейсхолдера: окончание зависит от подставленного значения | `{price}-ге сатып алу` → `Сатып алу: {price}` | high |
| `glossary_violation` | строгий термин из ТЗ переведён не по глоссарию | `семья → жанұя` вместо `отбасы` | medium |
| `inconsistent_term` | термин переведён не так, как в остальном файле, или оставлен по-русски | `ойнаушы` вместо `ойыншы`, `Предметті` вместо `Затты` | medium |

Как это работает:

- **orthography.** Частоты слов по всему kk-файлу. Редкое слово (1–2 раза) пробуем исправить
  заменой 1–2 букв по парам `а→ә, г→ғ, к→қ, н→ң, о→ө, у→ұ/ү, х→һ, и→і`. Если исправленный вариант
  встречается хотя бы 3 раза и в 3 раза чаще, это опечатка. Слова, которые есть в русском тексте
  той же строки (`торт`), не трогаем.
- **suffix_harmony.** Регулярка: `{x}` и сразу аффикс из `SUFFIXES` (с дефисом или без). Порядковые
  числа (`{place}-орын`) не считаются. Предлагаем переставить плейсхолдер после двоеточия;
  если фраза сложная (два плейсхолдера, тег), подсказку оставляем LLM и человеку.
- **glossary_violation** — только для терминов с `strict=1` (фракция, отбасы, бизнес, Grand Coins, варн).
- **inconsistent_term** — для остальных терминов, если файл почти единогласен (≥ 80% строк).
  Вариант, который встречается в ≥ 3 строках и ≥ 10% строк термина, считается устоявшимся,
  и ошибкой его не называем. Такие случаи `glossary_audit()` отдаёт лингвисту.

Строки пустые, совпадающие с ru или не на кириллице пропускаются: это `untranslated`,
`same_as_source`, `wrong_language`, у них приоритет выше.

## Казахская морфология в коде (`locqa/lang/kk.py`)

```python
from locqa.lang import kk

kk.stem("көлік")                       # 'көлі'  -> совпадает с көлігі, көліктер
kk.word_has_stem("отбасының", "отбасы") # True
kk.word_has_stem("үйрену", "үй")        # False: короткая основа требует настоящего аффикса
kk.harmonize("кітап", "dative")        # 'қа'
kk.split_affixes("ойнаушыларды")       # ('ойнаушы', ['лар', 'ды'])
kk.inflect("ойыншы", ["лар", "ды"])    # 'ойыншыларды'
```

`inflect` подбирает окончание по гармонии гласных и последнему звуку, поэтому исправления
сохраняют грамматику: `ойнаушыларды → ойыншыларды`, `Предметті → Затты`.

## Глоссарий

```csv
ru,kk,en,comment,allowed_variants,strict
семья,отбасы,family,"По ТЗ: семья = отбасы",,1
Grand Coins,Grand Coins,Grand Coins,"Бренд. Игроки говорят ГК / GC",GC|ГК,1
награда,сыйлық,reward,"сыйақы и марапат допустимы",сыйақы|марапат|жүлде|сый,
```

- `allowed_variants`: допустимые варианты через `|`, включая сленг игроков (варн, мут, фура, ГК).
- `strict=1`: термины из ТЗ, нарушение даёт `glossary_violation`.
- Колонку `ru` не менять без нужды: по ней термин ищется в русском файле с учётом окончаний
  (`семья / семьи / семьёй`, `уровень / уровня`).
- Глоссарий читают и проверки, и LLM-часть, поэтому `comment` пишем для людей и модели.

```python
from locqa.glossary import load_glossary, ru_has_term, kk_has_any
rows = load_glossary("glossary.csv")    # allowed_variants -> list
```

## Метрики

Валидационной выборки нет, поэтому меряем себя сами.

```bash
# Recall: известные ошибки в чистых строках, несколько сидов, среднее и разброс
python scripts/mutate_kk.py --source intl_ru.arb --target intl_kk.arb \
    --glossary glossary.csv --uz intl_uz.arb --seeds 7,11,23 --out recall.json

# Precision: выборка находок -> носитель ставит verdict 1 / 0 / t -> подсчёт
python scripts/precision_sample.py sample --report report.json --n 100 --out sample.csv
python scripts/precision_sample.py score sample.csv
```

Мутации повторяют ошибки, которые мы видели в файле: русская буква, латинская буква,
`{x}-ға` и `{x}ға`, синоним строгого термина, синоним-«соперник», оставленное русское слово,
сломанный плейсхолдер, пустая строка, узбекский текст.

Итоговая разметка: один носитель, 405 кандидатов; 378 подтверждений, 24 отклонения,
3 неопределённых решения. 94,03% подтверждений среди определённых. Четыре дополнительных
агентских исправления отмечены отдельно и не считаются проверкой носителя.

Мутационный тест имеет 11 вариантов, но покрывает 7 типов ошибок, а не все 11 типов кейса.
Полный офлайн-детектор включает кодовые проверки длины. Актуальная таблица генерируется
командой ниже; методы, ограничения и ручные метрики описаны в [methodology.md](methodology.md).

```bash
python scripts/compare_baselines.py --source data/intl_ru.arb --target data/intl_kk.arb \
    --glossary glossary.csv --en data/intl_en.arb --uz data/intl_uz.arb --seeds 7,11,23
```

## Окончания во время игры (`kk_affix`)

Вместо перефразирования строк с `{name}-ға` игра может склонять значение сама:
`kkInflect('Айдос', KkCase.dative)` → `Айдосқа`, `kkInflect('100', KkCase.dative)` → `100-ге`.
Пакет на Dart лежит в `integrations/flutter/kk_affix`, Python-версия в `locqa/lang/kk_runtime.py`,
обе сверяются на 343 общих примерах. Подробнее в [README пакета](../integrations/flutter/kk_affix/README.md).

## Бонус: латиница

```bash
python scripts/translit_kk.py intl_kk.arb --out intl_kk_latn.arb --report growth.csv
```

`ә→ä, ғ→ğ, қ→q, ң→ñ, ө→ö, ұ→ū, ү→ü, ш→ş, ы→y, і→ı, и/й→i` (в верхнем регистре `İ`).
Плейсхолдеры и теги не меняются, файл переписывается построчно, поэтому `@@comment` сохраняется.
В `growth.csv` попадают строки, которые выросли больше чем на 10% и на 3+ символа.

## Ревью носителем

1. `glossary.csv`: проверить `kk` и `allowed_variants`, причину правки писать в `comment`.
2. Разметить выборку для precision (`verdict`: 1 = ошибка, 0 = ложная тревога, t = не тот тип).
3. Ревью исправлений идёт через таблицы `--review-dir` (общий процесс в корневом README).

## Ограничения

- Статистика работает на больших файлах. На 200 строках срабатывают только детерминированные
  правила (латинские буквы, аффиксы после плейсхолдера, глоссарий).
- Если правильная форма слова в файле редкая, опечатку в ней статистика может не заметить.
- Синоним в длинном описании без «почти единогласного» термина пропускается: держим precision.
- `әр → ар` не ловится: `ар` тоже казахское слово.
